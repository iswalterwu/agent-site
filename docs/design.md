## 1. 背景、目标与成功标准

用户在终端里同时跑多个开发 agent（pi、DSH、Claude Code）时，经常忘记：

1. 每个 agent 现在在做什么；
2. 每个 feature 还差多少；
3. 遇到了什么问题；
4. agent 停在了哪里、是不是在等自己。

Agent Site 把每个项目的进展画成像素风的楼，把 agent 画成施工小人，常驻在屏幕右边缘，让这四件事一眼可见；同时让用户能在小窗里直接暂停一级、二级 agent，给它们建议，回答它们提出的决策。

### 1.1 成功标准（v1 验收口径）

| 编号 | 标准 | 验证方式 |
|---|---|---|
| SC-1 | 对工地上每个主 agent，5 秒内能看出：在做什么、属于哪个 feature 的哪一层、是否在等你、停在哪里（最后动作 + 多久前） | 人工验收（真实会话） |
| SC-2 | 楼段卡片里的进度数字全部来自 `specs/<feature>/spec.md` 的意图卡；卡片里没有的数字一律不显示、不推算 | 单元测试 + 人工核对 |
| SC-3 | 点"暂停"后，该 agent 的下一次工具调用不会执行，直到继续、给建议或中断 | 端到端测试 + 人工 10 次 |
| SC-4 | 给的建议会出现在该 agent 的下一次模型输入里 | 端到端测试 + 人工 |
| SC-5 | agent 调用 `ask_designer` 后 1 秒内出现决策弹框；在工地或终端回答都能回到 agent，先答的算数 | 端到端测试 + 人工 |
| SC-6 | 工地关闭或崩溃不会卡住任何 pi agent：暂停中的在 60 秒内自动放行，未答的决策回退 | 端到端测试 |
| SC-7 | 工地和桥接从不写入被监视仓库和各 harness 的目录 | 自动化测试（临时仓库前后比对）+ 代码审阅 |
| SC-8 | 画面无变化时，App 的 CPU 占用低于 2% | 人工测量 |
| SC-9 | 新事件发生后，桥接路径 0.5 秒内、日志路径 2 秒内在画面上可见 | 人工测量 |

## 2. 范围与术语

### 2.1 v1 做

- 右侧竖条常驻小窗：楼体、小人、气泡、卡片、决策弹框、系统通知、收起彩带。
- 只读读取：每个工地自己的 `specs/<feature>/spec.md` 意图卡、git 只读信息；pi / Claude Code / DSH 的本机会话日志。
- 控制（只对接入桥接的 pi 一级、二级 agent）：暂停、继续、立即中断、给建议（插话 / 做完再说）、回答决策。
- 指令台账、脱敏、演示模式、勿扰。

### 2.2 v1 不做

- 从工地启动新 agent（托管模式）。
- Claude Code、DSH 的控制（只读显示，标"只读"）。
- 修改被监视仓库的任何文件，包括派工模板和工作流文档。
- 三级及以下 agent 的控制（只显示）。
- 多用户、远程访问、联网同步、安装包。

### 2.3 术语

| 术语 | 含义 |
|---|---|
| 会话 | 一个 agent 的一次对话（pi 会话文件 / Claude Code 会话记录 / DSH 会话） |
| 一级 agent | 用户直接对话的会话，通常是协调者 |
| 二级 agent | 由一级 agent 派出的会话，如实施者、审核员 A |
| 三级 agent | 由二级派出的会话；只显示，不控制 |
| 主 agent | 一级和二级 agent |
| 桥接（site-bridge） | 装在 pi 个人扩展目录里的扩展，负责把 pi 会话接到工地 |
| 工地 | 一个工作目录：git 仓库（worktree 归到主仓库）或普通目录。一栋楼对应一个工地 |
| 工地 App | 本项目的 Electron 应用，一屏画一个工地 |
| 楼段 | 一个 feature 在楼里占的那一段 |

## 3. 核心取舍

独立项目、常驻置顶小窗、Electron + TypeScript、楼体按 feature 叠一栋楼、楼层对应意图卡切片、小人归属按证据强弱推断、只给一级 / 二级 agent 控制、桥接由用户自己装。完整的关键决定和各自的现行理由见 [architecture.md](architecture.md)。


## 4. 界面

### 4.1 小窗

- **位置与尺寸**：默认贴鼠标所在显示器工作区的右边缘，窗口高度 `min(工作区, 720 CSS px)`，剩余空间上下均分；工作区不足 720 时用满高度。像素画逻辑宽度 110 px，固定按 2 倍放大（楼体宽 220 px）；窗口左边一直留有 300 CSS px 的卡片位，所以窗口宽固定 520。`screen` 给的 `bounds` / `workArea` 和 `BrowserWindow` 一样是 DIP（4K 150% 的屏报 2560 宽），主进程直接按 DIP 定位和设尺寸，不再按 `scaleFactor` 换算；2× 在 DIP 上整数放大。接上 / 拔掉显示器、主屏或缩放变化时重新贴右缘；顶部 32 CSS px 拖动条可移动窗口，“附着到右侧屏幕”把窗口贴到当前屏右边最近的显示器，没有右侧屏时贴当前屏右缘；托盘可把窗口贴到主屏或鼠标所在屏幕，选过的屏拔掉后回主屏。
- **视觉标尺**：间距只取 0 / 4 / 8 / 12 / 16 / 24 / 32 / 48，窗口左右各 8 逻辑 px。画布字号两档：caption 5.5（2× 下 11 CSS px，用于楼层号、图例、气泡）、label 7.5（15 CSS px，用于楼段名、篷布、办公室）；卡片正文字号固定 14 CSS px、标题 18，标注与时间 12。中文正文行高 1.65，标题 1.3；字重只用 400 / 600。点击目标最少 32 CSS px（齿轮 32），焦点环 2 CSS px。
- **视觉令牌**：颜色、字号、间距、圆角、动效都收在 `src/app/theme.ts` 与 `index.html` 的语义层里，组件只引语义名。色值由 OKLCH 生成：中性色固定 H=250、L 步长 0.03–0.07、C ≤ 0.02；信号色只留琥珀（等你）、红（出错）、绿（在干）三族，停工用琥珀的亮档、空闲用中性灰；材质 C ≤ 0.06；业态色（塔楼青蓝、厂房锈红、临街店青与奶油）只用于楼段造型件和招牌件，不参与状态。表面用深板岩 `#13191f` 而不是纯黑，正文 `#dee2e5`、标注 `#94999e`；白昼配色见 WINDOW-26，只换外壳（面板、楼体剪影、边框、文字、地面）。压在楼体上的气泡、招牌、篷布底和楼层号一栏两套配色都用深色底 + 浅字（`theme.ts` 的 `PLATE`），不为每套配色重算一遍对比度；亮底上的强调文字和错误文字各用一档更深的橙、红（`index.html` 的白昼令牌）。
- **圆角与阴影**：卡片、菜单、摘要是 16 px 圆角；按钮、输入框、标签是 4 px。压在画布上的浮层（菜单、摘要）用不透明底色保证可读；卡片允许 6% 透明。卡片阴影两层，颜色带底色相，不用纯黑。
- **动效**：悬停反馈 120 ms、卡片进场 350 ms、退场按进场的 70%，只动 transform 与 opacity；`prefers-reduced-motion` 下关掉进场动画和过渡，保留颜色变化。等待灯约 800 ms 闪一次。
- **图标**：一律 24 viewBox、2 px 线宽、`currentColor`；齿轮和关闭用 SVG，不用字体符号。
- **展开**：完整的楼、小人、气泡。快照更新时楼体、灯、气泡、已打开的卡片和摘要一起更新，不自动展开、不抢焦点；普通更新不关卡片，只有对应 worker 离场时才关它的卡。
- **底栏**：固定 28 逻辑 px。第一行是 5 色图例（橙=等你、红=出错、黄=停工、绿=在干、灰=空闲），只有一行；第二行是每个会话一个指示灯，取全部工地——楼上只画当前工地，但别的工地有人在等你时这里也看得见（排序、上限和 `+N` 见 WINDOW-8，跨工地点灯见 WINDOW-21）。每盏 12×12 逻辑 px，2× 下 24×24 CSS，够点击目标；只读会话加空心圈。
- **收起**：贴边 8 px 的彩带，每段对应一个 feature，从下到上与楼段顺序一致。每段颜色取优先级最高的一项：橙色闪烁（有人等你）> 红（出错 / 测试失败）> 黄（停工）> 绿（有人在干）> 灰（没人）。收起时窗口边界仍是 520（收起不改窗口尺寸），只有彩带和左侧摘要卡可见，其余透明区穿透；悬停某段只显示该 feature 的摘要卡，不展开；右下角环走满 5 秒后锁定，锁定后指针离开或换段都不关，Esc / × / 展开解除。把窗口拖到工作区右缘 24 px 内或已经越过右缘，松开鼠标都吸回右缘，按窗口多数所在的屏算；吸附只改位置，窗口尺寸不变；拖动途中停顿不算松开，不吸；贴边隐藏开着时立即收起，卡片先关，即使有人等你；程序自己移动窗口不触发吸附。
- **展开与收起的切换**：
  - 点击彩带或摘要卡 → 展开；
  - 鼠标进过整窗后离开 3 秒 → 自动收起；刚启动、指针还没进过时不收；卡片开着时不自动收起；有人在等也照收，彩带闪橙色；
  - Esc → 收起；全局快捷键（默认 Ctrl+Alt+G，可改）→ 整体显示 / 隐藏。
- **鼠标穿透**：透明和空白区域把鼠标事件交给下面的窗口；小人、楼段、设计师、气泡、卡片、按钮、顶栏和齿轮可以点。主进程按 16 ms 轮询光标和渲染层上报的 CSS 命中矩形，切换 `setIgnoreMouseEvents`；光标和窗口内容边界都取 DIP，不二次缩放；不依赖渲染层的 mousemove。
- **置顶但不抢焦点**：窗口或弹框出现时只置顶显示，不夺走键盘焦点；点击窗口或任务栏才获得焦点。
- **卡片展开**：点楼段 / 小人 / 灯 / 气泡时，卡片画进窗口左边预留的 300 CSS px；再点同一个目标关掉。开卡片、切卡片、关卡片都不改窗口尺寸（透明窗口一改尺寸就会闪一帧桌面），右缘和楼体位置不动，没卡片时那块透明区仍穿透；指针停在空卡片位不算「在窗内」，贴边隐藏照常收起。卡片底色不透明、入场只滑不淡，画布单独成合成层，页面重绘时楼体不会被丢帧；卡片开着时指针离开整窗立即关闭，不必点 ×；指针留在窗内就保持；指针本来就在窗外时自动打开的决策卡保留，直到指针进出一次或点 × / Esc。对应楼段或办公室从快照消失时直接关它的卡。
- **任务栏与托盘**：窗口出现在任务栏；点窗口右下角齿轮打开窗内菜单，右键通知区工地图标打开托盘菜单，两处是同一份菜单模型（`src/app/menu.ts`）：显示（显示 / 隐藏）、位置（附着到右侧屏幕、贴到主屏、贴到鼠标所在屏幕）、工地（自动跟随 + 每个工地一项，带勾选；等待数见 WINDOW-13）、主题（夜色 / 白昼，带勾选，见 WINDOW-26）、行为（贴边隐藏、半透明、等待橙点、演示模式、勿扰、暂停动画，带勾选）二级菜单，设置、诊断和退出单列在分隔线下面（设置见 WINDOW-27）。"工地"组只在快照里有两处以上工地时出现；勾"自动跟随"就跟着最近有事件的工地走，勾某个工地就钉住它，钉住的工地从快照里消失时自动回到自动跟随。窗内菜单点组名或指针停在组上 120 毫秒展开二级菜单（换组重新计时，离开组取消待触发的计时）；二级菜单朝左展开、贴着所属组，最后一组先按往上顶排，仍会顶出窗口时上下挪回来，再放不下就自己滚动；指针离开整张菜单只收二级菜单；Esc 先收二级菜单、再按一次关整张菜单。菜单展开到左边的卡片位上，所以菜单开着时整窗都算「在窗内」，指针停在二级菜单上不会被自动收起或变半透明。“附着到右侧屏幕”选当前屏右边最近的显示器；没有右侧屏时贴当前屏右缘。左键显示 / 收起。高级项：贴边隐藏（关闭后离开不再自动收起）、半透明（指针在内容区里 100%、在外 42%，不改穿透；没开卡片和菜单时左边空卡片位算在外）、等待橙点（主进程按快照的等你状态给托盘图标加右上角橙点）、演示模式（隐藏气泡和卡片里的对话文字）、勿扰（压掉橙点和闪烁）、暂停动画（停闪烁，保留颜色）、诊断（来源、坏行、未知记录和解析问题）。
- **系统通知**：决策提问到达时的提醒见 WINDOW-22；"等你""停住""断线时暂停着"这三类状态提醒见 WINDOW-25。

界面语言和英文排版见 WINDOW-32 至 WINDOW-34，演示素材见 WINDOW-35；本文中的中文标签是中文界面示例，项目与会话原文不随界面语言改写。

### 4.2 楼体

- 一个 feature 一段楼，自下而上按配置顺序叠放；没有意图卡的工地没有 feature，按 SITE-7 的会话待办一段一会话叠放（见 4.3）。
- `placement = crown` 的 feature 画成楼顶的穹顶（配置里指定，没有默认），分层规则和普通楼段相同。
- `placement = office` 的 feature 画成地面上的工地办公室，不进主楼（配置里指定，没有默认）。治理类会话（见 4.4）也在这里。
- 材质表示前后端：后端 = 红砖，前端 = 玻璃幕墙，壳（Electron）= 金属，未归类 = 灰色混凝土。一个 feature 可以按比例分几种材质，从左到右排列。材质用低彩度底色加纹理：砖画错缝，玻璃画竖梃和上部反光，金属画板缝和铆钉，混凝土画模板缝；所有材质共用左上主光，上 / 左 1 px 亮边、下 / 右 1 px 暗边。有人站着的楼层把窗点亮，楼板下沿留一道暖光。
- 每段楼顶部左侧是楼段招牌（feature 名，前面 2 px 琥珀色标记）；楼层号写在左侧 15 逻辑 px 的编号栏里。连续未建的楼层只在段内画一圈虚线，内部留竖向骨架线，不画成黑盒子。
- feature 列表来自该工地 `specs/` 下带 `spec.md` 的目录；顺序、材质、placement 来自 App 配置。配置里没有的新 feature 用未归类材质，叠在最上面一段楼段之上、穹顶之下，诊断面板提示去补配置。
- 三种业态各有一套颜色和招牌件（见 WINDOW-30），材质和信号色不变：塔楼是冷钢蓝的玻璃纱、楼板下一道青蓝灯带、右缘竖向灯带、玻璃门厅和带灯的女儿墙；厂房是锈红壁柱、灰浆缝、通长横窗、卷帘门、锯齿屋顶加烟囱（烟只从屋顶上冒一点）；临街店是奶油墙、木饰线、大橱窗、每层一条青奶油条纹雨棚、灯笼和瓦檐。有人在的楼层把窗点亮，灯带、雨棚和灯笼常亮。同一段里每层长得不一样：塔楼窗格按层错位，每隔三层退进一侧做空中花园（栏杆、花箱、垂藤），顶部三层逐级退台，屋顶有花箱；厂房窗带高低和管道左右按层换，右缘外挂检修梯按整段高度画、每层一块落脚板，底层是带草地、树和木箱的院子，屋顶有烟囱和水塔；临街店每层是一间不同的店（咖啡、花店、书店、灯笼铺），每层一道外挑檐口、隔层外挑阳台，雨棚颜色、窗位、小门位置和装饰跟着换，屋顶有花箱；楼层号、步骤格和小人位置不变。造型件只画在 `placement = band` 的楼段里，落在楼段矩形内，不越到相邻段；段高不足 8 逻辑 px 时只画楼段本身，篷布段不画；crown 楼段的楼层画颜色和窗型，但不画屋顶和阶段件（它上面有自己的穹顶）；正在施工的当前切片保留步骤格，不叠窗型。窗型不随阶段收起，门和雨棚等楼段起到主体以后才装。
- 施工阶段跟工作项（切片或会话待办）的完成比例走（见 WINDOW-31）：围挡在段底（最厚 6 逻辑 px 的木板加立柱），地基是基坑加露出的钢筋，主体在段顶露钢筋，竣工才画屋顶。
- 穹顶和办公室也跟造型与阶段走（见 WINDOW-30、WINDOW-31）：穹顶 56×13 逻辑 px，塔楼是带青蓝底缘的半圆穹顶，厂房是锈红平顶设备间加奶油通风帽，临街店是瓦顶亭加暖灯招牌，三种都保留桅杆和旗，围挡到主体阶段也立着；办公室 12×8 逻辑 px，塔楼是现有的工地办公室，厂房是锈红板房加卷帘门，临街店是奶油墙、青雨棚加暖橱窗。
- 穹顶和办公室的四段：围挡是一圈木板围出的空地块，地基是基坑加钢筋，主体是没封口的钢架，竣工才画各自的形状；阶段跟各自 feature 的切片比例走，读不出或没有切片时停在围挡。
- 塔吊全楼只有一台，立在自下而上最高的主体阶段楼段上；crown 和 office 不立塔吊。塔吊和钢筋画在楼层号右侧、楼段右缘；小人、气泡和楼段招牌后画，压在施工件上。
- 矮楼：`specs/` 下没有带 `spec.md` 的目录、且没有带非空待办的一级会话时，`src/core/site.ts` 为它生成一层混凝土楼段，办公室为空；`src/app/layout.ts` 里单独算高度，不参与普通楼层的平分，这样冒出一个临时目录不会把整栋楼挤薄。有意图卡但读不出或缺切片的 feature 仍各占一段篷布楼段，不并进矮楼。画成什么样见 [requirements/site.md](requirements/site.md) 的 SITE-4。

### 4.3 楼层

有意图卡时，每段楼从下到上按"切片"一节的顺序排列：**一个切片一层**。没有意图卡时，按 SITE-7 一级会话的待办排列（pi 用桥接的 `site_todo` 记录，Claude / DSH 用各自的待办工具）：**一条待办一层**，`completed` 实体、`in_progress` 当前层、`pending` 虚线；最多 6 段、每段 12 层。顶部 32、底栏 28、地面 8 逻辑 px 固定，左右各 8；总层数是所有楼段的工作项数（切片或会话待办）之和；层高固定为 `楼体可用高度 / 10`（十层铺满），`楼段高 = 工作项数 × 层高`。不足十层时楼体只占底部一段，新增楼段或工作项让楼往上长；总层数超过十层才按比例收，楼层一起变薄，窗口宽高不变。楼体最底层固定画成实体（地基），脚手架从第二层起。

每层只有这几种画法：实体（已 ✓ 的切片）、虚线（还没到的切片）、当前切片的逐块进度。另外叠加脚手架（正在做）。

**推断规则**。输入只有解析后的意图卡；不读其他文件：

- 切片行尾标 `✓` → 实体。
- 当前切片（标 `（当前）` 的；没有标记时取第一个未 ✓ 的切片）有步骤 → 按步骤画格子：格数 = 步骤条数，`[x]` 画实心，其余画虚线框。
- 当前切片没写步骤 → 虚线。
- 其他没 ✓ 的切片 → 虚线。
- 所有切片都 ✓ → 整段实体，楼段状态为 done。
- **第一个未完成层**：自下而上第一个不是实体的层（虚线、当前没砌满都算）。
- **脚手架**：有小人归属在某层时画在那一层；没有小人时，状态为 in-progress 的 feature 画在第一个未完成层。
- **读不了的情况**：`spec.md` 读不出、缺 `## 切片` 一节 → 整段篷布写"图纸读不出"；有 `## 切片` 但一条切片都没有 → 整段篷布写"图纸未拆切片"。
- 步骤格子排在该层顶部一行，最多 16 逻辑 px 高；已完成的格子里画一个 ✓，没完成的只画虚线框。楼层号写在本层左侧编号栏的中线上。
- 画布固定按 2× 放大，1 逻辑 px = 2 CSS px；结构线用整数逻辑像素，细部（栏杆、竖梃、花茎）可以落在 0.5 逻辑像素，也就是 1 CSS px。测试会检查 `fillRect` 不出四分之一像素。

### 4.4 小人

**哪些会话上工地**：所有会话都上工地，按工作目录归到各自的工地（见下段）；一个工地里的会话满足以下任一条件就上工地：最近 24 小时（可配置）有新事件；桥接在线；有待回答的决策。超过时限没有动静或会话结束 → 收工离场：小人从原楼层水平走到窗口右缘并淡出（约 900 ms），其余小人不跳。楼体只画最近 6 小时有动静的等待 / 空闲会话；更早的等待 / 空闲仍留在快照和诊断里，但不进楼体、灯和等你清单，托盘等待橙点也按可见会话算。

**会话归到哪个工地**：跑一次 `git -C <工作目录> rev-parse --path-format=absolute --git-common-dir`，把公共 `.git` 的父目录当工地根，worktree 因此归到主仓库；不是仓库、git 失败或超时就用工作目录本身，算"普通目录"工地。工地名取目录名，配置里额外固定的工地用它给的名字，同名时按路径排序加 `#2`。没有工作目录的会话不进任何工地，诊断里留一条。

**层级**：

- pi（有桥接）：一级 = 用户在终端直接开的会话；一级会话里启动的 pi 子进程通过环境变量 `AGENT_SITE_PARENT_SESSION` / `AGENT_SITE_LEVEL` 继承父会话，成为二级；二级再派出的是三级。
- Claude Code（只读）：主会话 = 一级；`isSidechain` 为真的子 agent 记录 = 二级（具体存放方式以实测为准）。
- DSH（只读）：有子 agent 深度信息时按深度，否则按一级。
- pi（没装桥接、只有日志）：一律按一级。
- 三级及以下画成小号小人（7×8 逻辑 px），用虚线连到父级，没有控制按钮。
- 一级、二级小人 9×12 逻辑 px：8×11 的身体外再包 1 px 深色描边，压在砖墙或玻璃上也读得清。停工 / 出错时头顶两条竖线，等你时抬手，只读来源脚边一个空心圈。

**归属（feature + 楼层）**：有意图卡时按证据从强到弱，取第一条命中的；卡片里显示命中的是哪条。没有意图卡的工地，带待办的一级会话站自己那段（楼层取进行中或第一个未完成），子 agent 跟父会话站同一段，没有待办的会话仍站门口。

1. 手动钉住（存在 App 配置里，按会话 ID；可以同时钉住切片）。
2. 派工抬头：首条用户消息的第一行匹配 `# <feature> <阶段> [R<N>]`，且 feature 是已知 feature。抬头只用来认 feature。
3. 最近 20 次工具调用读写的 `specs/<feature>/…` 文件：按次计分，写 3 分、读 1 分，取得分最高的 feature。
4. 分支名或 worktree 目录名包含已知 feature 名（例如 `review/desktop-shell-…`）。
5. 治理类：最近 20 次工具调用里，一半以上涉及 `docs/`、`workflow/`、`templates/`、`AGENTS.md`、`HANDOFF.md`，并且没有 feature 证据 → 工地办公室。
6. 都没有 → 戴灰帽站在工地门口。

命中 feature 后，楼层统一取钉住的切片（在意图卡里存在时），否则第一个未完成层；全部完成时站最上面一层。

**角色**：派工抬头里的"你是 <角色>"（含"审核" → 监理；含"实施" → 工人；含"协调" → 工头）优先；其次是模型提示（`claude-fable-*` → 监理；`*gpt-*-astra*`、`deepseek-flash` → 工人；`claude-opus-*` → 工头。只作弱提示，因为 model-routing 的回退链会让同一个模型出现在不同角色上）；最后按层级默认（一级 → 工头，二级 → 工人）。

| 角色 | 外观 |
|---|---|
| 设计师（用户） | 不戴帽，拿蓝图卷 |
| 工头（协调者） | 红帽 + 对讲机 |
| 工人（实施者） | 黄帽 |
| 监理（审核员 A） | 白帽 + 夹板 |
| 临时工（三级） | 小一号，用虚线连到父级 |
| 未知 | 灰帽 |

帽子上有一个小圆点标模型家族：Claude、GPT、DeepSeek、其他。只读的小人（Claude Code、DSH、没装桥接的 pi）身上有"只读"小标。

**动作**（事件 → 动作 → 气泡）：

| 事件 | 判定 | 动作 | 气泡示例 |
|---|---|---|---|
| 读 / 搜索 | read、grep、find、ls、cat 等 | 展开图纸 | `看 plan.md` |
| 改代码 | edit / write，删除行 ≤ 新增行 × 2（行数按工具参数里的旧文本 / 新文本估算） | 砌墙 | `改 api.ts +12 −3` |
| 拆除 | 删除行 > 新增行 × 2，或 `rm`、`Remove-Item`、`git rm`、`git revert` | 抡大锤 | `删 legacy.ts` |
| 返工 | 同一会话里测试失败后 10 分钟内的修改 | 拆一块再砌一块 | `修 api.ts` |
| 测试 / 构建 | 命令匹配 pytest、vitest、`npm test`、`npm run build`、`vite build`、`playwright test` 等 | 拿水平仪检测：通过亮绿，失败冒烟 | `pytest ✗ 3` |
| 思考 | thinking 内容块；没有 thinking 块的来源，用不带工具调用的助手文本 | 挠头 + 思考泡 | 第一句（≤ 40 字） |
| 计划 / 待办 | 待办类工具调用，或修改 `tasks.md` | 翻清单 | 当前待办项 |
| 提交 | `git commit` 成功 | 在所在楼层浇一块楼板（闪一下） | 提交标题 |
| 派子 agent | 子 pi 会话带着本会话 ID 连上工地；或 Claude Code 的子 agent 工具调用 | 喊来一个临时工 | 派工标题 |
| 模型回退 | 模型切换记录 | 换帽子圆点颜色 | `换到 deepseek-flash` |
| 上下文压缩 | 压缩记录 | 蹲下整理工具箱 | `压缩上下文` |
| 限流 / API 报错 | 错误记录含 429、rate limit 等 | 坐下，头上闪电 | `限流，等待中` |

**状态**（叠加在动作之上，自上而下优先级递减）：

| 状态 | 判定 | 画法 |
|---|---|---|
| 等你决策 | 有未回答的 `ask_designer` | 走到设计师面前举手，橙色闪烁气泡显示问题前 40 字 |
| 已暂停 | 用户按了暂停（桥接上报） | 定住，头顶 ⏸，"已暂停：拦在 <工具> 之前" |
| 等你 | 回合结束且会话还开着。桥接：一级会话空闲；只读来源：最后一条是助手的回合结束，之后没有用户消息 | 举手，橙色气泡显示最后一句；只读来源前面加"可能" |
| 中途断掉 | 最后一个工具调用没有结果，且 30 分钟没有新事件（或桥接断线） | 定住，头顶 ⏸，"停在：<最后动作>" |
| 空闲 | 10 分钟没有新事件 | 坐着打盹，气泡显示最后动作 |
| 收工 | 会话结束（桥接发 `bye`），或超过上工地时限 | 走出工地 |

"等你"超过时限后，转入设计师清单的"历史"分组（时限见 WINDOW-20）。

**设计师**：站在地面、工地办公室旁边。只有用户亲手发出的消息才画成"设计师走过去交谈"：

- 一级会话里的用户消息，扣除桥接自己注入的那些（其他扩展注入的消息无法和手打的区分，按手打处理，这种情况少见）；
- 用户在工地里发出的建议。

协调者派给子 agent 的任务画成"工头去找临时工"，不冒充用户。

**气泡位置**：气泡画在楼内、工人所在层的上一层，最多两行（76 逻辑 px 宽，5.5 逻辑 px 字号），1 px 折线引到工人头顶，不盖住当前切片的步骤格子。默认只常显等你 / 出错 / 停工的气泡，其余点小人看卡片；多个气泡按 y 避让，拥塞时就近换层或上下错开，仍不盖当前切片的格子，不越出窗口。

### 4.5 卡片、弹框与控制

**小人详情卡**（从竖条向左弹出，占窗口左边预留的 300 CSS px，窗口尺寸不变）：

- 头部：角色 · feature · 楼层；状态和持续了多久；只读时说明原因。
- 现在：最多 4–5 句当前概况；等你时是问题原文，在干时优先取最后一段回复 / 思考，再退到最近动作。
- 会话：harness · 模型 · 会话短 ID（只留头尾）· 位置。
- 最近动作：最近 4 条，每条一行摘要，时间靠右且不换行。
- Trace：最近最多 10 条模型轨迹，每条标出提示 / 回复 / 思考 / 工具 / 结果 / 模型 / 压缩 / 报错，正文单行省略，时间靠右。
- 会话里的待办（能取到时显示）。
- 问题：最近的测试失败。
- 按钮：
  - 只读操作：在资源管理器中显示会话文件、复制会话 ID；
  - 工具自己的设置：改归属…、钉住 / 取消钉住；
  - 控制（仅限桥接在线的 pi 一级、二级）：暂停、继续、立即中断（需要二次确认）、给建议（输入框 + "插话" / "做完再说"）。桥接不在线时不出现控制按钮，只读时说明原因。
  - 待答决策：卡片显示问题预览和"打开决策卡"；决策卡收起或关闭后，提问仍保留在这里。

**楼段卡**：feature 名、状态、意图卡标题、风险档、验收例子数、待定条数、切片 done / total、当前切片的步骤 done / total、数据来源目录；按钮"在资源管理器中打开 specs/<feature>/"。意图卡读不出时显示"图纸读不出"，切片为空时显示"图纸未拆切片"。

**设计师卡（等你清单）**：列全部工地的等待项，分组和排序见 WINDOW-20；决策请求和回合结束的等待都在“现在”里。

**决策卡**：

- 由 agent 调用 `ask_designer` 触发（参数见 [architecture.md](architecture.md)「桥接协议 v2」），一级 / 二级会话的提问自动打开；三级会话的提问由 App 立即取消，不弹卡。
- 内容：谁在问（角色 · feature · 楼层）、问题、背景（可选）、选项按钮（0–6 个）、"其他…"输入框（允许时）、"取消这个提问"。
- 问题、背景和选项显示前脱敏；演示模式只显示"演示模式已隐藏决策内容"。
- 多个请求排队，一次只显示一个；回答受理后显示"已交给桥接，等收尾"，点"取消这个提问"则当场显示已取消（语义见 CONTROL-5）；卡片和普通卡一样离窗 3 秒或手动关闭，关闭卡不等于取消，提问仍留在工人卡里，可重新打开；`ask_resolved` 或会话离线才结束请求并移除入口。终端和 App 先答的算数。
- 弹出时置顶但不抢焦点；窗口没有焦点时的提醒见 WINDOW-22。

**控制语义**（只对桥接在线的 pi 一级、二级）：

| 操作 | agent 当时的状态 | 效果 |
|---|---|---|
| 暂停 | 运行中 | 当前工具调用照常做完；下一次工具调用在执行前被挂起。正在生成的回复不打断 |
| 继续 | 已暂停 | 放行被挂起的那次工具调用，原样执行 |
| 给建议 | 已暂停，且正挂起某次工具调用 | 拦下这次调用，拦截理由为"设计师暂停了这一步，并建议：<内容>"，同时解除暂停。模型立刻读到建议并重新规划 |
| 给建议 | 已暂停，但还没有挂起（仍在生成） | 以插话方式送达，同时解除暂停 |
| 给建议（插话） | 运行中 | `sendUserMessage(内容, { deliverAs: "steer" })`：当前这轮工具调用做完、下一次请求模型之前送达 |
| 给建议（做完再说） | 运行中 | `sendUserMessage(内容, { deliverAs: "followUp" })`：等它这一轮做完再送达 |
| 给建议 | 空闲（回合已结束） | 作为一条新的用户消息发出，开始新一轮 |
| 立即中断 | 任意 | 二次确认后调用 `ctx.abort()`，同时解除暂停 |

每条指令都等桥接回执；失败（断线、会话已结束）时在卡片里显示原因，不自动重试。

组件、数据流、桥接扩展与协议、主进程、渲染层、配置与数据目录、跨进程契约和关键决定见 [architecture.md](architecture.md)。

## 6. 出错处理

- **单个来源隔离**：每个读取器、每条桥接连接出错只影响它自己；小窗顶部显示各来源状态（pi / CC / DSH），诊断面板显示坏行数、认不出的事件数和最后一次错误。
- **坏行、认不出的记录**：跳过并计数。
- **意图卡读不了**：`spec.md` 读不出或缺 `## 切片` → 该楼段整段篷布写"图纸读不出"；切片为空 → "图纸未拆切片"。
- **文件被占用**：稍后重试；超大文件只按 architecture.md 里约定的范围读。
- **桥接断线**：小人标"失联"并保留最后状态；断线放行和回退见 [architecture.md](architecture.md)「桥接扩展 site-bridge」。
- **App 崩溃**：桥接按断线处理，agent 不受影响；App 重启后从日志补齐。
- **指令失败**：卡片里显示原因，不自动重试。

## 7. 安全与隐私

- **文件只读**：不写被监视仓库、`~/.pi`、`~/.claude`、`~/.dsh`；只写 App 数据目录。
- **不碰凭证**：读取器只按会话日志的路径规则打开文件，从不打开 `.env`、`auth.json`、`~/.dsh/.credentials.yaml` 等。
- **不联网**：App 与桥接只在 127.0.0.1 上通信；渲染层 CSP 禁止外部请求；没有遥测。
- **唯一的写入通道**：能影响 agent 的只有用户亲手触发的控制指令，全部记入台账。
- **本机口令**：每次启动重新生成，只存在 App 数据目录里。
- **脱敏**：显示前遮住疑似密钥（`sk-…`、`ghp_…`、`Bearer …`、AWS 密钥、长串十六进制 / base64）。唯一例外是设置面板里编辑 `settings.json` 的输入框（工地列表）：那是文件原文，遮了就没法编辑，所以照原样显示；面板里由程序拼出来的提示（含用户填的路径）照常先脱敏。
- **演示模式**：一键隐藏所有气泡和卡片里的对话文字，只留图标和状态。
- **全局扩展的范围**：桥接只在被监视仓库的会话里激活；由用户自己安装，可随时卸载（见第 10 节）。

## 8. 性能目标

- 事件到画面：桥接路径 ≤ 0.5 秒，日志路径 ≤ 2 秒。
- 画面无变化时 CPU < 2%，内存 < 300 MB。
- 启动时扫描最近 24 小时的会话 ≤ 5 秒。

## 9. 测试策略

原则：测真实实现，在系统边界注入，尽量少用 mock；不把真实会话内容放进仓库，测试样例全部照着真实格式手写。

1. **核心单元测试**（Vitest）：
   - 三种日志的事件统一；
   - 归属规则：派工抬头、specs 路径、分支名、治理类、门口、手动钉住的优先级；
   - 动作与状态判定：拆除 / 改代码的分界、返工、测试通过与失败、等你、中途断掉、空闲的阈值；
   - 楼层推断：切片 ✓ → 实体、当前切片按步骤砌、未到 → 虚线；缺切片 → 篷布；切片为空 → 未拆切片；全部 ✓ → 全部实体；
   - 脱敏规则。
2. **读取器集成测试**：在临时目录里分段追加、写半行、截断文件、更新 zstd 文件、目录增删。
3. **桥接测试**：在 pi 扩展 API 的边界注入假的 `pi` / `ctx` 对象，跑真实的桥接逻辑。重点是"不误拦"：
   - 未暂停时 `tool_call` 零等待；
   - 处理函数内部出错被接住，不向 pi 抛出；
   - 断线 60 秒自动放行；
   - App 离线时 `ask_designer` 正确回退；终端与工地同时回答时，先答的算数、另一边被取消；
   - 不属于被监视仓库的会话不连接；
   - 协议版本不符时停用。
4. **端到端测试**：用真实的 pi（`pi --mode rpc -e <桥接>`）跑小任务，模型换成测试专用的自定义 provider 返回预设回复，不花钱、不联网，覆盖 SC-3 ~ SC-6。自定义 provider 的写法是实施计划的第一批任务之一，先做可行性验证。
5. **只读保证测试**：给 App 一个临时仓库副本跑一轮，比对前后文件没有变化（SC-7）。
6. **本机冒烟测试**：读真实工地的 `specs/`，不崩、楼段数等于带 `spec.md` 的目录数；找不到路径时自动跳过。
7. **人工验收**：在真实的工地会话中逐条核对 SC-1 ~ SC-9。界面相关的几条要有具体动作：
   - 全局快捷键（WINDOW-23）：在编辑器里按 `Ctrl+Alt+S` 唤出 / 收起窗口；按 `Ctrl+Alt+P`，当前工地的 agent 在工具调用处停住，再按一次继续；先用别的程序占住 `Ctrl+Alt+S`，App 照常启动、其余功能正常，关掉那个程序并重启 App 后键位可用；退出 App 后这个键位能被别的程序注册。
   - 开机自启（WINDOW-24）：写 `"autostart": true` 重启 App，登录项里能看到一条；重启电脑后窗口自己出现；改回 `false` 重启 App 后那条消失；在限制启动项的环境里（组策略锁定）启动，App 照常运行，控制台有一行"没有生效"的警告。
   - 决策通知（WINDOW-22）：窗口被别的窗口盖住时让某个 agent 调用 `ask_designer`，桌面弹出"等你回答 · <工地名>"；点它，窗口到前台并拿到焦点；同一条不重复弹；打开勿扰后不再弹。
   - 待定进清单（WINDOW-28）：在某个工地的 `specs/<feature>/spec.md` 里加一行待定（`- 先定鉴权方式`），打开等你清单，历史下面出现 `<工地> · <楼段> · 先定鉴权方式`；打开「演示模式」再看，这一栏只显示条数、不显示文字。
   - 待做进清单（WINDOW-29）：在某工地的 `specs/backlog.md` 里加一行 `- 补导出`，打开等你清单，最后面出现 `<工地> · 补导出`；开演示模式后这一栏只显示条数。
   - 设置面板（WINDOW-27）：菜单「设置…」打开面板；把「空闲」写成 0 点保存，看到一条"空闲分钟要是大于 0 的数字"、文件没变；改成 5 保存后 `settings.json` 里是 5；把「停工」改得比「空闲」小，保存时提示"停工分钟要大于空闲分钟"；工地列表加一行 `/work/x = "名字"` 保存后，`settings.json` 的 `repos` 里多出这一条，写一行相对路径则报错且文件不变；在工地列表里打字时等一次快照刷新，输入不回退；点「厂房」保存后 `settings.json` 的 `style` 变成 `factory`，楼段、穹顶和办公室当场换造型，文件里已有的 `features[].style` 不被改动。
   - 造型与阶段（WINDOW-30、WINDOW-31）：给一个工地配一个 `crown` 和一个 `office`，切换三种造型看穹顶和办公室的形状；让某个 feature 的切片从 0 走到全部 ✓，看围挡、地基、主体、竣工四段；两个楼段都在主体时，塔吊只出现在上面那一段的右缘。
   - 主题（WINDOW-26）：写 `"theme": "day"` 重启，整座工地（楼体、卡片、菜单）是亮的；菜单「主题」里点「夜色」当场变暗，点回「白昼」再变亮；写成 `"dark"` 这种不存在的名字，启动后用默认的夜色并在诊断里看到一行。
   - 状态提醒（WINDOW-25）：把窗口失焦，再让一个会话停住（未返回的工具调用静默超过 `stalledMinutes`，默认 30 分钟，不是手动暂停），弹"停住了 · <工地名>"；状态一直挂着不再弹；该会话恢复干活再停住会重新弹。暂停一个会话后关掉那个 pi 会话（桥接掉线），弹"断线 · <工地名>"。

## 10. 安装与卸载

- **App**：`npm install` 后用 `npm start` 启动；不做安装包。开机自启由设置项 `autostart` 控制（WINDOW-24）。
- **桥接**（由用户亲自操作）：
  1. `npm run build:bridge`，生成 `dist/bridge/site-bridge.js`；
  2. 二选一：把该文件放进 pi 个人扩展目录（位置见 `pi config`），或在 pi 个人 `settings.json` 的 `extensions` 数组里加入它的绝对路径；
  3. 验证：在任一个工地上新开一个 pi 会话，2 秒内工地上出现对应的小人。
- **卸载**：删除该文件，或移除 `extensions` 里的那一项；App 数据目录可以整个删除。

## 13. 风险与开放问题

| 风险 | 影响 | 处置 |
|---|---|---|
| 桥接装在全局，一个 bug 可能卡住所有 pi 会话 | 高 | [architecture.md](architecture.md) 的桥接约定 + 第 9 节桥接测试；出问题时卸载即可恢复 |
| DSH 格式未公开、可能变化 | 中 | 只读、尽力解析；认不出就计数，在诊断面板提示 |
| Claude Code / pi 的日志格式升级 | 中 | 读取器按格式版本隔离；坏行计数 |
| 意图卡是手写 Markdown，格式可能不统一 | 中 | 解析只认模板里的固定小节；缺切片或读不出时该楼段盖篷布，不猜 |
| agent 不一定调用 `ask_designer`，仍可能在对话里直接提问 | 中 | 这种情况按"等你"显示；是否在被监视项目的 AGENTS.md 里写明它的用法，由用户决定 |
| 右侧竖条会压住其他窗口的右侧（包括 Claude 应用的侧栏） | 低 | 已选定竖条；靠收起、穿透、一键隐藏缓解 |
| 显示器缩放（125% / 150%）或外接屏切换时像素发虚 / 窗口居中 | 中 | 工作区和光标坐标都用 Electron 给的 DIP，不二次缩放；画布按设备像素建位图；监听显示器增删和缩放变化，重新贴边并重画；仍需人工验收 125% / 150% 与外接屏 |
