# SITE：工地的发现与范围

代号：SITE

> **读我**：本文列出工地怎么从会话里认出来、切换和降级显示的现行要求，每条都有编号、例子和证明方式。界面和楼体细节见 [design.md](../design.md) 第 4–5 节；窗口行为见 [window.md](window.md)，桥接侧见 [control.md](control.md)。

## 发现

- SITE-1：工地的范围按会话的工作目录自动认定，不靠配置里的仓库名。git 仓库里的会话归到仓库根，worktree 归到同一个仓库；不是仓库的目录自己成一个工地。
  - 例：给定仓库 `a` 里的一个会话和 `a` 的一个 worktree 里的会话，两处归到同一个工地；给定 `b` 目录里的会话，它自己成一个工地。
  - 证明：`tests/main/repo.test.ts` 中的 "SITE-1 …"；`tests/main/engine.test.ts` 中的 "SITE-1 …"
- SITE-5：默认配置里不含任何具体项目名，没有 `repos`、`features` 也能用。
  - 例：删掉 `settings.json` 启动，工地照常成形，诊断里只有"feature 不在 features 里"这类提示。
  - 证明：`tests/main/settings.test.ts` 中的 "SITE-5 …"

- SITE-6：引擎里能安全清理的缓存都会清：会话文件没了之后它的状态跟着清掉；快照里没有的工地 specs 缓存会被清掉；一小时内没用过的键与分支缓存会被清掉（"用过"按命中算，不是按第一次算出来）。文件还在的会话状态一律保留（重新读只能恢复头尾两段，中段补不回来），所以会话状态的总量不保证有界。
  - 例：删掉一个会话文件，来源统计里它的会话数归零；同一个目录隔一小时后才来新会话，工地键要重新问一次 git；文件还在的老会话即使过了窗口期也保留状态。
  - 证明：`tests/main/engine.test.ts` 中的 "SITE-6：会话文件没了之后…"、"SITE-6：窗口期外但文件还在的会话保留状态"、"SITE-6：键缓存闲置一小时就清掉"、"SITE-6：分支缓存也是闲置一小时才清"、"SITE-6：工地从快照里消失后…"

- SITE-7：`specs/` 下没有带 `spec.md` 的目录时，每个带非空待办的一级会话占一段楼段。楼段名取会话第一条提示的首行（脱敏、最多 16 个字符），没有首行时用 `<harness> · <会话短 ID>`，重名时补 4 位会话短 ID；楼层自下而上按待办顺序排列，`completed` 是实体、`in_progress` 是当前层、`pending` 是虚线；楼段卡标"来自会话待办"，显示待办 done / total 和当前待办，不显示风险、AC、待定。最多 6 段、每段最多 12 层，超出的会话和待办只在诊断里说明；没有待办的会话仍站在门口。有意图卡的工地不参与这一条。
  - 例：两个没有 specs 的会话各有 3 条待办（完成 / 进行中 / 未开始各一条），楼里出现两段各 3 层，高度一致；第三个没有待办的会话站在门口。
  - 证明：`tests/core/building.test.ts` 中的 "SITE-7 …"、`tests/app/cards.test.ts` 中的 "SITE-7 …"

## 当前工地与切换

- SITE-2：一个工地一栋楼；快照里带全部工地和一个当前工地，当前工地默认是最近有事件的那个。
  - 演示：同时跑两个仓库的会话，工地自动落在刚有新动静的那个。
  - 证明：`tests/core/snapshot.test.ts` 中的 "SITE-2 …"；`tests/main/engine.test.ts` 中的 "SITE-2 …"；`tests/app/layout.test.ts` 中的 "SITE-2 …"
- SITE-3：菜单里可以钉住某个工地或改回自动跟随；被钉住的工地消失时回到自动跟随；只有一个工地时菜单不出现这一组。
  - 演示：菜单选另一个工地，工地换过去；那个工地关掉后，画面回到自动跟随。
  - 证明：`tests/app/sites.test.ts` 中的 "SITE-3 …"；`tests/app/menu.test.ts` 中的 "SITE-3 …"

## 矮楼与边界

- SITE-4：`specs/` 下没有带 `spec.md` 的目录、且没有一个一级会话带非空待办时，工地画成一层混凝土矮楼，高度不超过可用楼体高度的四分之一；名字牌是工地名，楼段卡不显示楼层和进度数字，摘要写"没有意图卡"；矮楼不盖篷布、不搭脚手架。有意图卡但读不出或缺切片的 feature 不算矮楼，各占一段篷布楼段（`图纸读不出` / `图纸未拆切片`）。
  - 例：一个只有代码没有 `specs` 的仓库跑一个会话，工地出现一层矮楼，名字是目录名；一个有 `alpha`、`beta`、`gamma` 三张意图卡的仓库，即使三张都没拆切片，也画三段篷布，三个会话各站自己那段。
  - 证明：`tests/core/snapshot.test.ts` 中的 "SITE-4 …"；`tests/app/layout.test.ts` 中的 "SITE-4 …"；`tests/main/engine.test.ts` 中的 "SITE-4：仓库里没有意图卡…"、"SITE-4：有意图卡但没切片的工地不画矮楼…"

## 验证

- 工地键、worktree 归一、非 git 目录、同名工地编号和没有工作目录的会话用临时仓库和临时会话日志测。
- 多工地的快照结构、当前工地的选择和钉住后的回退用纯函数测；菜单形状和托盘模板用菜单模型测。
- 矮楼的高度、工人站位和楼段卡用布局与卡片的单测覆盖；真实 App 里钉住一个非 git 目录的工地是人工验收步骤。
