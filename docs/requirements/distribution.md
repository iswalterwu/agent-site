# DIST：桌面分发与 DSH 插件

代号：DIST

> **读我**：本文列出 Windows 桌面组件、DSH 启动插件及商店分发的现行要求。模块和启动契约见 [architecture.md](../architecture.md) 的「DSH 插件与桌面分发」；窗口、语言和控制分别沿用 WINDOW 与 CONTROL。

## 桌面组件与插件包

- DIST-1：提供 Windows 11 x64 免安装 ZIP，完整解压后可直接运行 Agent Site，无需用户克隆源码或另外安装 Node.js、npm、Electron；不要求管理员权限，不静默注册开机自启。组件支持含空格和中文的安装目录，原有窗口、语言、工地显示与 pi 桥接行为不变；macOS、Linux、Windows ARM64 不宣称为本版支持平台。
  - 例：在不含 Node.js 的 Windows 11 x64 测试环境解压到带空格的目录，运行程序看到空工地；退出后原有用户文件不变。

- DIST-2：桌面组件提供与可执行文件同目录的 `agent-site.json`，包含产品标识、精确 SemVer 版本、平台 `win32`、架构 `x64`、启动协议 `1`。插件只接受用户配置的本机绝对 `.exe` 路径及其同目录清单；路径不存在、不是文件、清单缺失或无效、产品/平台/架构/协议不符时不启动进程，给出可读的修正说明，不向用户显示异常堆栈。
  - 例：路径指向不存在的文件时提示重新选择完整解压的组件；清单的启动协议为未知值时提示组件不兼容，不执行该文件。

- DIST-3：提供独立的预构建 `dsh-agent-site` 插件 `.tgz`，包含可加载的 `dsh.bundle.patch`、宿主和客户端入口、双语元信息及所需静态文件；根包保持 `private: true`。安装插件不编译源码、不下载或启动桌面组件，不带 Electron 运行时；DSH 运行时依赖使用宿主共享实例。首版在 DSH `0.2.1-rc.3` 与 `0.2.2-rc.1` 的隔离环境验证，包中兼容声明仅覆盖这两个精确版本，不宣称其他版本可用。
  - 例：向隔离 profile 安装 `.tgz` 后，DSH 能加载插件；未配置桌面组件也不影响宿主启动。兼容范围外的 DSH 按宿主包兼容检查得到可读提示，不靠强行覆盖宿主依赖继续安装。

## 插件入口与启动

- DIST-4：启用插件后，在 DSH 原有插件详情页提供 Agent Site 入口，复用宿主配置控件管理当前 profile 的可执行文件路径，并提供「打开工地」和桌面组件下载入口。未配置时以下载组件为主操作，并有聚焦路径配置的次操作；保存了非空路径后以打开工地为主操作，下载降为次操作。未配置、已配置、未保存修改、请求中、请求已发送、失败的状态可区分；只有用户主动打开才发起启动。路径输入由宿主配置表单管理，空值表示未配置；只有保存成功的配置用于打开，未保存修改期间先提示保存，保存失败保留草稿和原配置。插件自身的状态与反馈不回显机器绝对路径；程序文案跟随宿主中英文界面，不翻译外部原文，显示反馈沿用脱敏规则。
  - 例：首次进入可直接打开公开下载页面或用次操作聚焦路径字段，但不能启动空路径；配置有效组件后点击「打开工地」，按键在请求期间不可重复提交；键盘可以完成配置和打开。

- DIST-5：插件仅通过宿主已有的认证请求通道接受当前 owner 的打开操作，协议版本为 `1`。打开请求不能夹带命令、参数、工作目录或会话根；可执行文件路径只由 owner 经宿主配置流程单独保存，启动时宿主仅从已保存配置和 DSH 环境取值。宿主检查本机 Windows x64 平台，用独立参数数组直接启动目标文件，不使用 shell，并移除子进程环境中的 `ELECTRON_RUN_AS_NODE` 和 `NODE_OPTIONS`。非法请求、未授权请求和不支持的平台不得产生进程；失败不给宿主造成未处理异常，不增加监听端口、模型工具或模型请求。
  - 例：提交未知协议或在请求里夹带命令路径被拒绝；从 Desktop 的 Node 模式宿主打开时，Agent Site 仍作为独立 GUI 运行，而不是继承 RunAsNode 模式。
  - 例：远程访问部署或非 Windows x64 宿主不承诺在浏览器所在电脑打开窗口，入口明确说明适用范围。

- DIST-6：打开响应区分已发送与可本地化的失败原因；「已发送」只表示系统进程启动已提交，不冒充窗口已就绪或会话已读到。客户端最多等待 8 秒，超时或断连说明结果尚未确认，不自动重发，也不把迟到响应改成新的请求结果；用户再次操作仍须主动点击。外部错误仅脱敏保留，不按错误文字猜测词条。
  - 例：宿主不回答时结束等待并显示可读提示；期间点击不会发送第二个请求，超时后不会后台重试。可执行文件被移走或启动被系统拒绝时显示失败原因，DSH 仍能正常使用。

## 数据根、单实例与生命周期

- DIST-7：App 与 snapshot CLI 按显式 `--dsh-home`、非空 `DSH_HOME`、默认 `~/.dsh` 的优先级解析 DSH 数据根，再派生 `sessions`；空白环境值视为未设置。插件启动使用 `--agent-site-launch=1 --dsh-home <绝对目录>`；`--dsh-home` 也可独立用于直接启动或 snapshot CLI。路径展开当前用户的 `~` 后仍非绝对，或参数缺值、重复、未知协议、路径无效时，给可读错误并以非零状态退出；尚不存在的合法绝对根可正常显示无会话，不创建该目录。App 保存阈值重开引擎后仍使用同一根；pi / Claude 的读取根、旧设置文件和无参数启动保持兼容，不迁移或改写会话。
  - 例：只有自定义 DSH 根内有合成会话，首次打开和保存新阈值后都能读到；未设置任何覆盖值时沿用原来的默认目录。
  - 例：`--dsh-home` 缺值时不创建窗口、不回退到默认根扫描，输出可读说明；指向尚不存在的合法目录时显示空工地且目录仍不存在。

- DIST-8：App 保持单实例。再次指定同一 DSH 根只复用已有窗口，不重置卡片、控制状态或未发送草稿；明确指定不同根时，已有 App 保留当前根和状态，提示先退出再从目标 DSH 打开，不静默切换。没有指定新根的普通再次打开仍复用窗口。既有开机自启按 WINDOW-24 的开关执行，登记参数携带当前 DSH 根；插件不启用自启，不自行写注册项。
  - 例：从同一 profile 连续两次打开只出现一个工地窗口；从另一数据根打开时，原有工地和草稿保留，能看到冲突说明。
  - 例：在自定义根下由用户启用自启，登记参数可以在下次登录恢复这个根；自启关闭时不会因安装插件而开启。

- DIST-9：插件禁用、卸载或 DSH 退出后，入口及其请求处理资源撤销，但已经打开的 App 独立运行；不终止 App、不删除组件/App 数据或会话，不安装/修改 pi 桥接。DSH 在工地内仍按 CONTROL-3 只读。回滚插件使用 DSH 官方卸载入口，桌面组件可换回兼容旧版；关闭自启后可移走便携目录，App 数据与 Harness 数据均保留。
  - 例：窗口打开后在 DSH 禁用插件，入口消失而窗口仍在；退出并重开 DSH 不会自动再启动窗口，用户仍可直接运行桌面程序。

## 视觉与图文

- DIST-11：插件使用原创像素楼体 Logo，采用 24×24 整数网格及无损 PNG，包清单、插件详情和组件行能读取同一图标，不使用宿主默认拼图作为正常展示；商店图标也使用该像素标识。描述以中英文准确说明 pi、Claude Code、DSH 的桌面像素会话监控，不把插件表述为模型、调度器或 DSH 控制器。自有区域采用像素招牌风格：方角 4px、琥珀强调、深灰表面；宿主标题、卸载开关、组件及来源信息保持宿主所有，不全局改写其样式。自有正文 16px、标注最小 14px、标题与操作有明确层次，字体不因拉窄而缩小；间距沿 4/8 基准，文字对比度不低于 4.5:1，控件边界不低于 3:1，点击目标不小于 44×44 CSS px。令牌集中定义颜色、字阶和尺度，样式限定在插件区域；原有未保存草稿、错误反馈、双语和保存语义不变。
  - 例：打开插件页可看到楼体与吊臂构成的像素 Logo、简短描述、产品展示和独立配置区；375 CSS px 和桌面宽度下均无插件区域横向溢出，焦点可见且操作可达。

- DIST-12：插件自带静态产品效果图，使用真实渲染器的虚构会话画面，显式标注虚构数据与模拟桥接，不使用实际会话、用户路径或账户信息。图片、Logo 随预构建包离线提供，不为展示而访问第三方图床；Logo 单文件不超过 10KB，产品主图不超过 120KB。产品图按 CSS 展示尺寸提供 1×/2× 资源，声明尺寸或宽高比及清楚的替代文字，首屏图不懒加载；图片损坏时显示可读替代提示，配置和打开功能仍可使用。商店截图列表只引用同一插件目录内的安全图片，不把测试环境截图直接发布；减少动态效果偏好下不自动播放装饰动图。
  - 例：断开外网后，插件 Logo 与产品图仍显示，图注说明示例并非真实在线桥接；人为破坏主图时，仍能保存路径和使用打开操作，不出现缺图导致的页面溢出。

## 分发与收录

- DIST-10：正式制品仅从已审核的公开仓库提交构建，发布文件按白名单收集，提供精确版本、ZIP、插件 `.tgz`、SHA-256 校验值和中英文安装/卸载/回滚说明；不包含真实会话、profile、凭证、私人原型、开发历史或本机路径，保留必要第三方许可证。版本、产品标识和兼容声明在制品与说明中一致；构建或隐私检查失败不上传。商店材料如实声明 Windows 本机、桌面组件需单独解压、DSH 只读，带公开安全示例图。公开代码同步、Release 上传和商店 PR 各自需在执行前授权；本版不发 npm、不自动更新或后台下载，任何发布失败都报告已完成步骤与恢复方法，不擅自继续后续步骤。
  - 例：从干净公开 checkout 构建后检查归档与校验值，仅出现发行所需文件；安装说明同时覆盖 DSH Desktop 的实际 profile 与本机 `dsh web`，不让用户默认都装进 `web`。
  - 例：未获 Release 上传授权时只生成本地制品和收录草稿，不上传、不创建 PR；同意上架后仅新增自己的目录条目，不改生成的 README 或他人插件信息。
